Tutorial Prático: fundamentos de sistemas web e desenvolvimento de aplicação NestJS para upload e visualização de CSV

Este tutorial foi elaborado para estudantes iniciantes, que ainda não possuem familiaridade com a estrutura de aplicações web. Por essa razão, o material começa com uma explicação teórica sobre como sistemas web são organizados e como seus componentes interagem. Em seguida, apresenta-se o desenvolvimento prático de uma aplicação em NestJS capaz de receber um arquivo CSV, armazená-lo no servidor e exibir seu conteúdo em uma tabela HTML.

Objetivos da atividade

Ao final deste estudo, o aluno deverá compreender a estrutura básica de um sistema web, distinguir os papéis do navegador e do servidor, reconhecer a função de rotas, controllers, services e views, preparar um projeto no Windows com Visual Studio Code, integrar GitHub e GitHub Copilot ao processo de desenvolvimento e implementar uma aplicação funcional em NestJS para upload e visualização de arquivos CSV.

1. Antes de programar: o que é uma aplicação web?

Uma aplicação web é um sistema acessado por meio de um navegador, como Chrome, Edge ou Firefox. Quando o usuário digita um endereço ou clica em um botão, o navegador envia uma solicitação para um servidor. O servidor processa essa solicitação, executa alguma lógica e devolve uma resposta. Essa resposta pode ser uma página HTML, dados em formato JSON, uma imagem, um arquivo ou uma mensagem de erro.

Ideia central: em uma aplicação web, o navegador faz pedidos e o servidor responde.

Por exemplo, quando o usuário acessa uma página de upload de arquivo, o navegador solicita ao servidor a página HTML correspondente. Depois, quando o usuário seleciona um arquivo e clica em enviar, o navegador envia esse arquivo ao servidor, que o recebe, processa e devolve uma nova resposta.

2. Como navegador e servidor se comunicam

A comunicação entre navegador e servidor normalmente ocorre por meio do protocolo HTTP. Esse protocolo organiza a troca de mensagens em dois elementos principais: a requisição e a resposta.

Requisição: mensagem enviada pelo cliente ao servidor.
Resposta: mensagem enviada pelo servidor ao cliente.

O navegador atua como cliente. O servidor executa a aplicação. Quando o navegador precisa de alguma coisa, ele envia uma requisição. Quando o servidor termina o processamento, ele envia uma resposta.

Algumas requisições pedem apenas para visualizar uma página. Outras enviam dados ao servidor. É por isso que existem diferentes métodos HTTP, como GET e POST.

Método Uso mais comum Exemplo
GET Solicitar dados ou páginas Acessar a página de upload
POST Enviar dados ao servidor Enviar um arquivo CSV

3. Front-end e back-end

Em sistemas web, costuma-se dividir a aplicação em duas grandes partes. A primeira é o front-end, que corresponde à interface visível ao usuário. A segunda é o back-end, que executa a lógica do sistema, processa dados, salva arquivos e responde às solicitações.

Front-end: parte visual com a qual o usuário interage.
Back-end: parte lógica que processa requisições e manipula dados.

Nesta atividade, a página HTML de upload e a tabela exibida no navegador são parte da experiência visível ao usuário. Já o NestJS, que recebe o arquivo, salva no disco e lê o CSV, corresponde ao back-end.

4. O que significa modelar um sistema web

Modelar um sistema web significa organizar suas partes de modo que cada componente tenha uma responsabilidade clara. Em vez de escrever todo o programa em um único arquivo, a aplicação é dividida em elementos com funções específicas. Essa organização facilita a leitura, a manutenção, a correção de erros e a evolução do sistema.

Em termos didáticos, pode-se pensar no sistema como um fluxo:

Usuário → Navegador → Rota → Controller → Service → Arquivo ou dado → Resposta → Navegador

Cada parte do fluxo cumpre uma função específica. O aluno precisa entender esse caminho antes de começar a programar, porque o código em NestJS reflete exatamente essa organização.

5. Componentes básicos de uma aplicação em NestJS

O NestJS é um framework para desenvolvimento de aplicações no lado do servidor com TypeScript. Ele organiza o sistema em módulos, controllers e services. Para um iniciante, é importante entender cada um desses elementos separadamente.

Módulo: agrupa partes relacionadas do sistema.
Controller: recebe a requisição e define o que será feito.
Service: executa a lógica de negócio ou processamento.
View: página HTML que será mostrada ao usuário.

Nesta atividade, o controller será responsável por receber o arquivo enviado e por chamar o service. O service será responsável por ler o CSV. A view será responsável por mostrar o formulário de upload e depois exibir os dados em tabela.

6. Entendendo o papel das rotas

Uma rota é um endereço da aplicação que representa uma funcionalidade. Quando o navegador acessa esse endereço, o servidor executa o código associado a ele.

Por exemplo:

Rota Método Função
/csv/upload GET Exibir a página com o formulário de upload
/csv/upload POST Receber o arquivo enviado pelo usuário
/csv/view/:filename GET Ler o arquivo salvo e mostrar a tabela

Observe que a mesma rota pode existir com métodos diferentes. Isso acontece porque uma coisa é pedir a página para envio do arquivo, e outra é efetivamente enviar o arquivo ao servidor.

7. Como os dados circulam nesta atividade

O fluxo completo da atividade pode ser entendido em etapas.

  1. O usuário abre a página de upload no navegador.
  2. O navegador faz uma requisição ao servidor.
  3. O servidor responde com uma página HTML contendo um formulário.
  4. O usuário escolhe um arquivo CSV e envia o formulário.
  5. O navegador envia o arquivo ao servidor.
  6. O controller recebe esse arquivo.
  7. O sistema salva o arquivo na pasta uploads.
  8. O usuário acessa uma rota de visualização.
  9. O controller chama o service para ler o arquivo CSV.
  10. O service transforma o conteúdo em dados estruturados.
  11. O controller envia esses dados para uma view.
  12. A view gera uma tabela HTML e a exibe no navegador.
Antes de programar, é essencial que o aluno consiga explicar esse fluxo com suas próprias palavras. Isso reduz a chance de copiar código sem compreender sua função.

8. O que é um arquivo CSV e por que ele é útil

CSV significa Comma-Separated Values, ou valores separados por vírgula. Trata-se de um formato de arquivo textual usado para representar dados tabulares. Cada linha normalmente representa um registro, e os valores de cada coluna são separados por vírgulas.

Exemplo:

nome,idade,cidade Ana,21,Campinas Bruno,22,São Paulo Carla,20,Valinhos

Nesse exemplo, a primeira linha contém os nomes das colunas: nome, idade e cidade. As linhas seguintes contêm os dados.

9. Estrutura lógica da solução que será construída

A aplicação desta atividade será organizada em quatro camadas simples:

  1. Interface de upload: uma página HTML com formulário para envio do arquivo.
  2. Recebimento e armazenamento: uma rota no back-end que recebe o arquivo e salva na pasta do projeto.
  3. Leitura do CSV: um service que abre o arquivo e interpreta suas linhas.
  4. Exibição em tabela: uma view que recebe os dados e monta a tabela HTML.

20. Definindo explicitamente os nomes das views

Antes de construir o controller, é importante definir formalmente os nomes e a localização física das views da aplicação. Neste tutorial, será utilizado o mecanismo de templates Handlebars, configurado com a extensão .hbs. Isso significa que as páginas renderizadas pelo servidor não devem ser salvas como .html, mas como arquivos .hbs dentro da pasta views.

View 1: views/upload.hbs — formulário para envio do arquivo CSV.
View 2: views/table.hbs — página para exibição dos dados do CSV em formato tabular.

O nome de cada arquivo precisa corresponder exatamente ao nome informado no decorator @Render() do controller. Em outras palavras, quando o código usar @Render('upload'), o NestJS irá procurar o arquivo views/upload.hbs. Da mesma forma, quando o código usar @Render('table'), o framework irá procurar o arquivo views/table.hbs.

Decorator no controller Arquivo físico correspondente Finalidade
@Render('upload') views/upload.hbs Exibir o formulário de upload
@Render('table') views/table.hbs Exibir os dados do arquivo CSV
Um erro comum entre iniciantes é salvar as views como upload.html e table.html. Neste projeto, como a engine configurada é hbs, os arquivos corretos devem ser upload.hbs e table.hbs.

21. Pensando antes do controller

O controller será o ponto de entrada das requisições relacionadas ao CSV. Sempre que o navegador acessar uma rota definida nele, o NestJS executará o método correspondente. Nesta atividade, o controller terá três responsabilidades:

  1. mostrar a página de upload;
  2. receber e salvar o arquivo enviado;
  3. solicitar a leitura do arquivo e enviar os dados para a view de tabela.

22. Código do controller

import { Controller, Get, Post, UploadedFile, UseInterceptors, Render, Param, Res, BadRequestException } from '@nestjs/common'; import { Response } from 'express'; import { FileInterceptor } from '@nestjs/platform-express'; import { diskStorage } from 'multer'; import { CsvService } from './csv.service'; @Controller('csv') export class CsvController { constructor(private readonly csvService: CsvService) {} @Get('upload') @Render('upload') uploadPage() { return {}; } @Post('upload') @UseInterceptors( FileInterceptor('file', { storage: diskStorage({ destination: './uploads', filename: (req, file, cb) => { cb(null, Date.now() + '-' + file.originalname); }, }), fileFilter: (req, file, cb) => { if (!file.originalname.toLowerCase().endsWith('.csv')) { return cb(new Error('Apenas arquivos CSV são permitidos.'), false); } cb(null, true); }, }), ) uploadFile( @UploadedFile() file: Express.Multer.File, @Res() res: Response, ) { if (!file) { throw new BadRequestException('Nenhum arquivo CSV foi enviado.'); } return res.redirect(`/csv/view/${file.filename}`); } @Get('view/:filename') @Render('table') async viewFile(@Param('filename') filename: string) { const data = await this.csvService.parseCsv(filename); return { data, filename }; } }

Explicação linha a linha:

@Controller('csv'): define o prefixo das rotas deste controller.

constructor(private readonly csvService: CsvService) {}: injeta o service para que ele possa ser usado dentro do controller.

@Get('upload'): cria a rota GET /csv/upload.

@Render('upload'): informa que essa rota irá renderizar a página views/upload.hbs.

uploadPage() { return {}; }: retorna um objeto vazio para a view.

@Post('upload'): cria a rota POST /csv/upload para envio do arquivo.

@UseInterceptors(...): ativa o mecanismo que captura o arquivo enviado.

FileInterceptor('file', ...): indica que o campo de formulário chamado file é o arquivo.

destination: './uploads': define onde o arquivo será salvo.

filename: (req, file, cb) => { ... }: define a lógica do nome do arquivo no disco.

Date.now() + '-' + file.originalname: adiciona data e hora ao nome para reduzir conflitos.

fileFilter: cria uma validação do tipo de arquivo.

endsWith('.csv'): verifica se o nome termina com .csv.

@Res() res: Response: permite controlar diretamente a resposta HTTP.

if (!file): valida se algum arquivo foi realmente recebido.

throw new BadRequestException(...): interrompe a execução com erro adequado quando não há arquivo enviado.

return res.redirect(`/csv/view/${file.filename}`): após o upload, redireciona o navegador para a rota de visualização do CSV, em vez de exibir JSON bruto.

@Get('view/:filename'): cria uma rota com parâmetro dinâmico.

@Render('table'): informa que essa rota irá renderizar a página views/table.hbs.

@Param('filename'): captura o valor do nome do arquivo na URL.

const data = await this.csvService.parseCsv(filename);: pede ao service para ler o arquivo.

return { data, filename };: envia os dados para a view da tabela.

23. Pensando antes do service

O service é usado para separar a lógica de processamento. Em vez de fazer toda a leitura do arquivo dentro do controller, deixamos essa responsabilidade em outro componente. Isso melhora a organização e torna o código mais fácil de manter.

24. Código do service

import { Injectable } from '@nestjs/common'; import * as fs from 'fs'; import * as csv from 'csv-parser'; @Injectable() export class CsvService { parseCsv(filename: string): Promise { return new Promise((resolve, reject) => { const results: any[] = []; fs.createReadStream(`uploads/${filename}`) .pipe(csv()) .on('data', (data) => results.push(data)) .on('end', () => resolve(results)) .on('error', (error) => reject(error)); }); } }

Explicação linha a linha:

import * as fs from 'fs';: importa o módulo de leitura de arquivos do Node.js.

import * as csv from 'csv-parser';: importa a biblioteca que interpreta o CSV.

@Injectable(): informa ao NestJS que esta classe pode ser injetada.

parseCsv(filename: string): Promise<any[]>: cria um método que recebe um nome de arquivo e retorna uma lista de linhas.

const results: any[] = [];: cria a estrutura que guardará os dados lidos.

fs.createReadStream(`uploads/${filename}`): abre o arquivo salvo na pasta uploads.

.pipe(csv()): envia o conteúdo para o interpretador CSV.

.on('data', (data) => results.push(data)): adiciona cada linha do arquivo ao vetor.

.on('end', () => resolve(results)): quando termina, devolve os resultados.

.on('error', (error) => reject(error)): em caso de erro, interrompe com falha.

25. Pensando antes das views

As views são páginas HTML que o servidor monta e envia ao navegador. Aqui usaremos Handlebars, que permite inserir valores dinâmicos na página. Em vez de criar HTML fixo, podemos passar dados do controller para a view.

26. Arquivo views/upload.hbs

A seguir está o conteúdo da primeira view da aplicação. Este arquivo deve ser salvo com o nome upload.hbs dentro da pasta views. Ele será utilizado pela rota GET /csv/upload quando o controller executar @Render('upload').

<!DOCTYPE html> <html lang="pt-BR"> <head> <meta charset="UTF-8"> <title>Upload de CSV</title> </head> <body> <h1>Enviar arquivo CSV</h1> <form action="/csv/upload" method="post" enctype="multipart/form-data"> <input type="file" name="file" accept=".csv" required> <button type="submit">Enviar arquivo</button> </form> </body> </html>

Explicação:

Essa página mostra um formulário. O atributo action="/csv/upload" indica para onde os dados serão enviados. O método post indica que o formulário enviará dados ao servidor. O atributo enctype="multipart/form-data" é obrigatório para upload de arquivos. O nome físico do arquivo deve ser upload.hbs, pois ele corresponde ao decorator @Render('upload') utilizado no controller.

27. Arquivo views/table.hbs

A segunda view da aplicação deve ser salva com o nome table.hbs dentro da pasta views. Ela será utilizada pela rota GET /csv/view/:filename quando o controller executar @Render('table').

<!DOCTYPE html> <html lang="pt-BR"> <head> <meta charset="UTF-8"> <title>Visualização do CSV</title> </head> <body> <h1>Dados do arquivo {{filename}}</h1> {{#if data.length}} <table border="1" cellpadding="8" cellspacing="0"> <thead> <tr> {{#each data.[0]}} <th>{{@key}}</th> {{/each}} </tr> </thead> <tbody> {{#each data}} <tr> {{#each this}} <td>{{this}}</td> {{/each}} </tr> {{/each}} </tbody> </table> {{else}} <p>O arquivo não possui dados para exibição.</p> {{/if}} </body> </html>

Explicação:

Essa página recebe o nome do arquivo e os dados lidos do CSV. O bloco {{#if data.length}} verifica se há conteúdo. O bloco {{#each data.[0]}} usa a primeira linha para descobrir os nomes das colunas. O bloco {{#each data}} percorre todas as linhas. Dentro dele, {{#each this}} percorre os valores de cada linha. O nome físico do arquivo deve ser table.hbs, pois ele corresponde ao decorator @Render('table') utilizado no controller.

31. Síntese conceitual final

Ao concluir esta atividade, o aluno deverá ser capaz de descrever o sistema nos seguintes termos: o navegador envia uma requisição, o controller recebe essa requisição, o service executa a leitura do arquivo, a view organiza a apresentação dos dados e o servidor devolve a resposta ao usuário.
