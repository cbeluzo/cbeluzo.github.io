Tutorial completo: criando um sistema básico de formulários em NestJS com salvamento em arquivos TXT

Neste tutorial, vamos construir passo a passo uma aplicação web muito simples em NestJS. O sistema terá uma página inicial, dois formulários HTML, processamento dos dados enviados pelo usuário e salvamento dessas informações em arquivos .txt. Ao final, também teremos páginas para listar os registros salvos e visualizar o conteúdo de cada arquivo. O objetivo é apresentar uma base clara, simples e funcional, desde a criação do projeto até sua execução no navegador.

1. O que será construído

O projeto final será uma aplicação web com as seguintes funcionalidades: uma página inicial com links de navegação, um formulário de cadastro de pessoa, um formulário de solicitação, salvamento dos dados enviados em arquivos de texto, uma página de listagem dos arquivos salvos e uma página de visualização detalhada de cada registro.

Resumo do fluxo: o usuário abre uma página HTML, preenche um formulário, envia os dados ao servidor, o NestJS processa as informações, salva um arquivo .txt e depois exibe uma resposta no navegador.

2. Tecnologias utilizadas

Vamos utilizar NestJS, Node.js, TypeScript, Handlebars para renderização de views HTML e o módulo fs do Node.js para gravar e ler arquivos de texto no disco.

Tecnologia Função no projeto
Node.js Ambiente de execução JavaScript/TypeScript no servidor
NestJS Framework para organizar a aplicação
Handlebars (hbs) Engine de views HTML
fs Leitura e escrita de arquivos TXT

10. Configurando o arquivo main.ts

O arquivo main.ts é o ponto de entrada da aplicação. É nele que o NestJS é inicializado. Também é nele que vamos informar onde estão as views e qual engine será usada para renderizar as páginas HTML.

Substitua o conteúdo de src/main.ts por:

import { NestFactory } from '@nestjs/core'; import { AppModule } from './app.module'; import { join } from 'path'; async function bootstrap() { const app = await NestFactory.create(AppModule); app.setBaseViewsDir(join(__dirname, '..', 'views')); app.setViewEngine('hbs'); await app.listen(3000); } bootstrap();

Explicação linha a linha:

import { NestFactory } from '@nestjs/core';: importa a função que cria a aplicação NestJS.

import { AppModule } from './app.module';: importa o módulo principal do projeto.

import { join } from 'path';: importa a função usada para montar caminhos de pastas.

const app = await NestFactory.create(AppModule);: cria a aplicação.

app.setBaseViewsDir(...): informa onde estão os arquivos de views.

app.setViewEngine('hbs'): define Handlebars como mecanismo de renderização.

await app.listen(3000): inicia o servidor na porta 3000.

11. Criando o service de formulários

O service ficará responsável por salvar os dados em arquivos TXT, listar os arquivos gravados e ler um arquivo específico.

Substitua o conteúdo de src/form/form.service.ts por:

import { Injectable } from '@nestjs/common'; import * as fs from 'fs'; import * as path from 'path'; @Injectable() export class FormService { private readonly basePath = path.resolve(process.cwd(), 'data', 'forms'); constructor() { if (!fs.existsSync(this.basePath)) { fs.mkdirSync(this.basePath, { recursive: true }); } } savePersonForm(data: { nome: string; email: string; telefone: string; cidade: string }) { const id = Date.now().toString(); const filename = `person-${id}.txt`; const filePath = path.join(this.basePath, filename); const content = `Tipo: cadastro_pessoa ID: ${id} Nome: ${data.nome} Email: ${data.email} Telefone: ${data.telefone} Cidade: ${data.cidade} `; fs.writeFileSync(filePath, content, 'utf-8'); return filename; } saveRequestForm(data: { nome: string; assunto: string; descricao: string; data: string }) { const id = Date.now().toString(); const filename = `request-${id}.txt`; const filePath = path.join(this.basePath, filename); const content = `Tipo: solicitacao ID: ${id} Nome: ${data.nome} Assunto: ${data.assunto} Descricao: ${data.descricao} Data: ${data.data} `; fs.writeFileSync(filePath, content, 'utf-8'); return filename; } listRecords() { if (!fs.existsSync(this.basePath)) { return []; } return fs.readdirSync(this.basePath).filter((file) => file.endsWith('.txt')); } readRecord(filename: string) { if (filename.includes('..') || filename.includes('/') || filename.includes('\\')) { throw new Error('Nome de arquivo inválido.'); } const filePath = path.join(this.basePath, filename); if (!fs.existsSync(filePath)) { throw new Error(`Arquivo não encontrado: ${filename}`); } return fs.readFileSync(filePath, 'utf-8'); } }

Explicação do código:

@Injectable() marca a classe como um serviço que pode ser usado pelo NestJS.

basePath define, de forma explícita, a pasta onde os arquivos TXT serão gravados e lidos.

O constructor() garante que a pasta data/forms exista. Isso evita falhas de gravação em ambientes limpos, nos quais o diretório ainda não foi criado.

savePersonForm(...) recebe os dados do formulário de pessoa, monta o conteúdo textual e grava um arquivo.

saveRequestForm(...) faz a mesma coisa para o formulário de solicitação.

listRecords() lista os arquivos TXT existentes na pasta. Se a pasta não existir, retorna um vetor vazio.

readRecord(filename) lê o conteúdo de um arquivo específico, mas antes valida o nome informado e verifica se o arquivo realmente existe.

12. Criando o controller de formulários

O controller definirá as rotas do sistema. Ele será responsável por exibir as páginas HTML, receber os dados enviados pelos formulários e chamar o service para salvar ou recuperar informações.

Substitua o conteúdo de src/form/form.controller.ts por:

import { Body, Controller, Get, Param, Post, Render } from '@nestjs/common'; import { FormService } from './form.service'; @Controller() export class FormController { constructor(private readonly formService: FormService) {} @Get() @Render('home') home() { return {}; } @Get('forms/person') @Render('person-form') personForm() { return {}; } @Post('forms/person') @Render('success') submitPersonForm( @Body() body: { nome: string; email: string; telefone: string; cidade: string }, ) { const filename = this.formService.savePersonForm(body); return { mensagem: 'Cadastro de pessoa salvo com sucesso.', filename, }; } @Get('forms/request') @Render('request-form') requestForm() { return {}; } @Post('forms/request') @Render('success') submitRequestForm( @Body() body: { nome: string; assunto: string; descricao: string; data: string }, ) { const filename = this.formService.saveRequestForm(body); return { mensagem: 'Solicitação salva com sucesso.', filename, }; } @Get('records') @Render('records') records() { const files = this.formService.listRecords(); return { files }; } @Get('records/:filename') @Render('record-detail') recordDetail(@Param('filename') filename: string) { const content = this.formService.readRecord(filename); return { filename, content }; } }

Explicação detalhada:

@Controller() indica que a classe agrupa rotas da aplicação.

@Get() define rotas acessadas por requisições GET, normalmente usadas para abrir páginas.

@Post() define rotas usadas para receber dados enviados por formulário.

@Render('home'), @Render('person-form'), @Render('request-form') e demais usos de @Render informam qual view será mostrada.

@Body() captura os dados enviados pelo formulário.

@Param('filename') captura o nome do arquivo informado na URL.

Quando o formulário é enviado, o controller chama o método correspondente do service, grava o TXT e retorna uma página de sucesso.

Observação importante sobre a leitura dos arquivos: o controller está adequado para a listagem e a leitura. Em geral, quando a funcionalidade /records não mostra arquivos, o problema costuma estar no serviço, especialmente no caminho da pasta, na ausência do diretório data/forms ou na tentativa de ler um nome de arquivo inexistente.

14. Criando a view do formulário de pessoa

Crie o arquivo views/person-form.hbs com o conteúdo abaixo:

<!DOCTYPE html> <html lang="pt-BR"> <head> <meta charset="UTF-8"> <title>Cadastro de pessoa</title> </head> <body> <h1>Cadastro de pessoa</h1> <form action="/forms/person" method="post"> <div> <label for="nome">Nome:</label> <input type="text" id="nome" name="nome" required> </div> <div> <label for="email">E-mail:</label> <input type="email" id="email" name="email" required> </div> <div> <label for="telefone">Telefone:</label> <input type="text" id="telefone" name="telefone"> </div> <div> <label for="cidade">Cidade:</label> <input type="text" id="cidade" name="cidade"> </div> <button type="submit">Salvar cadastro</button> </form> <p><a href="/">Voltar para a página inicial</a></p> </body> </html>

Explicação:

Cada campo possui um atributo name. É esse nome que o NestJS usará para montar o objeto recebido em @Body().

Crie o arquivo views/success.hbs com o conteúdo abaixo:

<!DOCTYPE html> <html lang="pt-BR"> <head> <meta charset="UTF-8"> <title>Sucesso</title> </head> <body> <h1>Operação realizada com sucesso</h1> <p>{{mensagem}}</p> <p>Arquivo gerado: <strong>{{filename}}</strong></p> <p><a href="/records">Ver lista de registros</a></p> <p><a href="/">Voltar para a página inicial</a></p> </body> </html>

Essa página usa variáveis vindas do controller: {{mensagem}} e {{filename}}.

17. Criando a view de listagem de registros

Crie o arquivo views/records.hbs com o conteúdo abaixo:

<!DOCTYPE html> <html lang="pt-BR"> <head> <meta charset="UTF-8"> <title>Registros salvos</title> </head> <body> <h1>Registros salvos</h1> {{#if files.length}} <ul> {{#each files}} <li> <a href="/records/{{this}}">{{this}}</a> </li> {{/each}} </ul> {{else}} <p>Nenhum registro encontrado.</p> {{/if}} <p><a href="/">Voltar para a página inicial</a></p> </body> </html>
Se a página de listagem abrir, mas não mostrar nenhum item, verifique se houve gravação efetiva de arquivos na pasta data/forms. A rota de listagem depende diretamente do retorno de listRecords().

Explicação:

{{#if files.length}} verifica se existem arquivos para exibir.

{{#each files}} percorre a lista de nomes de arquivos enviada pelo controller.

{{this}} representa o item atual do laço.

18. Criando a view de detalhe do registro

Crie o arquivo views/record-detail.hbs com o conteúdo abaixo:

<!DOCTYPE html> <html lang="pt-BR"> <head> <meta charset="UTF-8"> <title>Detalhe do registro</title> </head> <body> <h1>Detalhe do registro</h1> <p><strong>Arquivo:</strong> {{filename}}</p> <pre>{{content}}</pre> <p><a href="/records">Voltar para a lista de registros</a></p> <p><a href="/">Voltar para a página inicial</a></p> </body> </html>

O elemento <pre> preserva a quebra de linhas do conteúdo do arquivo TXT.

19. Verificando o módulo principal

Normalmente, ao gerar o módulo e o controller, o NestJS já atualiza o app.module.ts. Mesmo assim, é importante conferir.

O arquivo src/app.module.ts deve estar semelhante a isto:

import { Module } from '@nestjs/common'; import { AppController } from './app.controller'; import { AppService } from './app.service'; import { FormModule } from './form/form.module'; @Module({ imports: [FormModule], controllers: [AppController], providers: [AppService], }) export class AppModule {}

O ponto principal é que o módulo FormModule apareça dentro de imports.

22. O que acontece internamente quando o formulário é enviado

Quando o usuário preenche um formulário e clica no botão de envio, o navegador cria uma requisição HTTP do tipo POST e envia os dados para a rota definida no atributo action. O NestJS recebe essa requisição no método do controller correspondente. Esse método usa @Body() para acessar os campos enviados. Em seguida, o controller chama o service. O service monta um texto com os valores recebidos, grava o arquivo no disco e devolve o nome do arquivo criado. Por fim, o controller retorna uma view HTML de sucesso para o navegador.

Fluxo resumido: formulário HTML → requisição POST → controller → service → gravação do TXT → resposta HTML.

23. Possíveis erros básicos e como verificar

Problema Causa comum Como verificar
Página não encontrada Nome incorreto da rota ou da view Conferir o nome usado em @Get, @Post e @Render
View não renderiza Arquivo .hbs ausente ou em pasta errada Confirmar se o arquivo está em views/
Arquivo TXT não aparece na listagem Pasta data/forms não foi criada ou o salvamento falhou Confirmar se o diretório existe e se o constructor() do service está criando a pasta automaticamente
Listagem vazia mesmo após salvar Caminho incorreto da pasta de dados Conferir o valor de basePath e, se necessário, registrar esse caminho no console durante os testes
Erro ao abrir um registro Arquivo inexistente ou nome inválido na URL Verificar a implementação de readRecord(filename) e testar o tratamento para arquivos ausentes
Dados vazios Campo name do HTML não corresponde ao esperado no controller Comparar os nomes dos campos do formulário com o objeto recebido em @Body()

24. Ajustes de robustez recomendados

Após testar o projeto completo, recomenda-se adotar três medidas no serviço de arquivos. A primeira é garantir a criação automática da pasta data/forms no constructor(). A segunda é utilizar um caminho absoluto resolvido a partir da raiz de execução, reduzindo problemas relacionados ao diretório corrente do processo. A terceira é validar o nome do arquivo antes da leitura e verificar explicitamente se o arquivo existe, evitando erros inesperados e melhorando a segurança da aplicação.

Em termos práticos: o controller pode permanecer praticamente igual. O ganho principal está em tornar o FormService mais confiável para gravação, listagem e leitura dos arquivos.
